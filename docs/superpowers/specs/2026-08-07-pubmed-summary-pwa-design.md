# PubMed 综述 PWA 设计规格

日期：2026-08-07

## 1. 目标

将现有 n8n 工作流迁移为可部署到 GitHub Pages 的纯前端 PWA。应用由用户提供自己的 DeepSeek API Key 和 My NCBI API Key，在浏览器内完成 PubMed 检索、摘要处理、中文综述生成、引用整理和 Word 导出。

系统不得依赖自建后端、Serverless Function、数据库服务或飞书。用户密钥、文献数据、中间结果和历史记录均仅保存在用户设备上。

## 2. 已确认的产品决策

- 主界面采用单列“聚焦工作台”，历史与设置为次级入口。
- 用户输入自然语言研究主题；DeepSeek 生成 PubMed 检索式后，必须先让用户编辑和确认。
- 最大抓取量可在 10–300 篇之间调整，默认 50 篇。
- 抓取后新增相关性筛选阶段；筛选后不设置固定篇数上限，由模型上下文预算动态确定最终入选集。
- 尽量保留现有 n8n 的检索式生成、综述大纲、正文写作和引用重排流程。
- 原 n8n 中经过调试的三组提示词作为迁移基线，不主动改写其内容。
- DeepSeek 模型可在当前账户可用的 Flash 和 Pro 模型间选择，默认 Flash。模型列表优先从 DeepSeek API 动态读取。
- 检索词可使用中文或英文，最终综述固定输出中文。
- 完成后直接下载 DOCX，不在网页中预览或编辑综述正文。
- DOCX 只包含综述标题、正文及正文实际引用的参考文献。
- 历史记录保留检索信息、文献元数据、摘要、筛选结果、阶段结果、最终综述和参考文献。
- API Key 保存在当前浏览器，关闭并重新打开应用后仍可使用。
- PWA 在桌面端和手机端均可安装。离线时可查看历史和重新导出 Word，但不能发起检索或 AI 生成。
- 不接入飞书，不保留飞书 Webhook、消息回复、云文档、凭据或任何飞书相关模块。

## 3. 范围外事项

- 不提供用户注册、登录、云同步或跨设备同步。
- 不提供服务端密钥代理或服务端任务队列。
- 不抓取付费全文，也不绕过出版商访问控制。
- 不在浏览器内提供富文本或 Markdown 正文编辑器。
- 不将生成结果自动发送到飞书或其他第三方平台。
- 不承诺 AI 生成内容的医学结论绝对正确；应用仅提供来源映射和结构完整性校验。

## 4. 系统架构

### 4.1 托管与运行边界

GitHub Pages 仅托管构建后的静态 HTML、CSS、JavaScript、图标和 Service Worker。所有业务逻辑在用户浏览器内运行：

- NCBI Client：调用 ESearch 和 EFetch。
- DeepSeek Client：读取模型列表并调用聊天补全接口。
- Workflow Engine：执行阶段状态机、取消、重试和恢复。
- PubMed Parser：解析 XML 并标准化文章元数据。
- Relevance Filter：分批评估文献相关性并生成结构化筛选结果。
- Context Budgeter：估算输入规模并构建可放入目标模型上下文的入选集。
- Citation Processor：校验引用编号、按首次出现顺序重排并生成参考文献。
- DOCX Exporter：在浏览器内生成 Word 文件。
- Local Repository：使用 IndexedDB 保存设置、任务、文章和检查点。
- Service Worker：缓存应用外壳，不缓存 API 请求、响应或密钥。

应用不包含任何隐藏的后端依赖。若 NCBI 或 DeepSeek 未来取消浏览器跨域调用支持，应用应显示明确的兼容性错误；不得悄悄切换到未声明的代理服务。

### 4.2 技术栈

- React、TypeScript、Vite。
- 基于 Vite 的 PWA/Service Worker 集成。
- IndexedDB 封装库，用于版本化数据模型和事务。
- 可靠的 XML 解析库，不使用正则表达式解析 PubMed XML。
- 浏览器端 DOCX 生成库。
- 测试栈包括单元测试、组件/集成测试和 Playwright 端到端测试。

GitHub Pages 部署使用静态构建产物和仓库子路径兼容的资源基址。应用不得依赖服务端路由；可使用单页状态切换或兼容静态托管的路由方式。

## 5. 工作流

### 5.1 设置与连接检查

1. 首次打开时，用户填写 DeepSeek API Key 和 My NCBI API Key。
2. 应用遮盖显示密钥，并提供单独的连接测试。
3. DeepSeek 连接测试读取可用模型列表；优先展示当前可用的 Flash 和 Pro 模型，不依赖旧的硬编码模型名。
4. NCBI 连接测试执行轻量请求，验证 API Key 是否可用。
5. 只有两个连接均通过或用户明确跳过测试后，才允许开始任务。

PWA 不要求或保存 My NCBI 用户名和密码。

### 5.2 新建任务

1. 用户输入自然语言研究主题或检索要求。
2. 用户选择 DeepSeek 模型和最大抓取量，范围为 10–300，默认 50。
3. 应用调用“生成 PubMed 检索式”提示词。
4. 页面展示生成的检索式，允许用户编辑。
5. 应用查询预计命中数并显示给用户。
6. 用户确认检索式后，正式任务开始并写入第一个检查点。

### 5.3 PubMed 检索与解析

1. 使用 ESearch 获取 PMID 集合和历史查询信息。
2. 使用 EFetch 分页获取 XML，避免单个请求过大。
3. 解析 PMID、标题、摘要、作者、期刊、发表日期、单位及 PubMed 提供的其他必要标识。
4. 没有有效摘要的文章标记为排除，不进入后续 AI 处理。
5. 每个文章对象使用稳定的内部来源 ID；PMID 是主要外部标识。
6. 抓取和解析结果立即写入 IndexedDB 检查点。

### 5.4 相关性筛选

1. 使用独立的新提示词，将标题和摘要按安全批次发送给 Flash 模型。
2. 模型必须返回结构化结果，包括内部来源 ID、相关性评分、纳入/排除决定和简短原因。
3. 应用拒绝未知 ID、重复 ID 或缺失 ID，并对无效批次执行有限次数的格式修复或重试。
4. 文献按相关性评分排序；同分时保持 PubMed 原始顺序，确保结果可复现。
5. 筛选日志保存在历史记录中，但不写入最终 Word。

### 5.5 动态上下文预算

筛选后不设置固定篇数上限。Context Budgeter 按以下规则构建最终入选集：

1. 根据所选模型的能力表确定保守上下文上限；未知模型使用保守回退值。
2. 估算原提示词、检索要求、文献字段和格式开销的 token 数量。
3. 为大纲或正文输出、引用和 API 协议开销预留安全空间。
4. 按相关性从高到低加入完整文章，直到下一篇文章会突破安全预算。
5. 不截断单篇摘要，不拆散文章元数据与摘要。
6. 历史记录保存“相关但因上下文预算未入选”的文章及原因。

如果没有文章通过筛选，任务停止并提示用户修改研究主题或检索式后重新运行，不继续产生大纲和正文调用费用。

### 5.6 综述生成与引用

1. 将最终入选文章整合为与原 n8n 工作流等价的摘要输入。
2. 生成参考文献候选列表，并为每篇文章保留稳定来源 ID。
3. 调用原“综述框架”提示词生成中文写作大纲。
4. 调用原“综述写作”提示词生成中文 Markdown 综述。
5. 扫描正文引用，只接受映射到实际入选文献的引用 ID。
6. 引用和参考文献按正文首次出现顺序重新编号。
7. 无效引用触发局部修复；修复失败时，任务进入可重试的“引用校验失败”状态，不导出带有虚假编号的 Word。

引用校验保证编号存在、映射唯一和列表顺序一致，但不把“文献确实支持该句医学主张”作为可自动证明的条件。

### 5.7 Word 导出

1. DOCX 包含一个标题、分级正文标题、自然段、正文引用和最终参考文献列表。
2. Word 中不加入检索式、模型名、筛选统计、运行日志或全文摘要附录。
3. 任务完成后自动触发 DOCX 下载。
4. 页面只显示完成状态、抓取数、有效摘要数、入选数和“再次下载”操作，不展示综述正文。
5. DOCX 二进制不长期存入 IndexedDB；再次下载时由保存的最终内容重新生成。
6. 文件名使用清理后的综述标题和日期，移除操作系统不允许的字符。

完整运行数据可由用户主动导出为 JSON，文献清单可单独导出为 CSV。这两类文件不得包含 API Key。

## 6. 原提示词迁移规则

需要迁移的原提示词为：

- 生成 PubMed 检索式。
- 综述框架。
- 综述写作。

迁移要求：

- 从 `D:\BaiduSyncdisk\n8n\PubMed summary.json` 的 UTF-8 内容提取提示词；不得把包含凭据的完整工作流 JSON 复制到仓库。
- 保留提示词正文、角色定义、约束、输出格式和阶段顺序。
- 只替换 n8n 表达式、节点引用和变量插值语法，使其接收类型明确的浏览器端数据。
- DeepSeek 请求适配放在 API Client 层，不通过重写业务提示词完成。
- 三个原提示词分别存放、带版本号，并使用快照测试防止无意改写。
- 新增的相关性筛选提示词独立存放，不拼接或改写原提示词。

## 7. 用户界面

### 7.1 聚焦工作台

工作台始终以当前任务为中心：

- 顶部显示产品名、历史入口和设置入口。
- 主区显示研究主题输入、模型选择、最大抓取量和“生成检索式”。
- 检索式生成后，原位置切换为可编辑的检索式、预计命中数和“开始生成”。
- 运行时显示单一总进度和当前阶段：抓取、解析、筛选、大纲、写作、引用校验、Word 生成。
- 用户可取消任务；已经完成的阶段保持在历史记录中。
- 完成后自动下载并显示“再次下载”。

桌面端使用居中的单列工作区。手机端保持相同操作顺序，控件纵向排列，历史和设置使用适合触控的次级导航。

### 7.2 历史

历史列表按时间倒序显示主题、状态、创建时间、抓取数和入选数，并支持：

- 继续或重试未完成任务。
- 再次生成并下载 Word。
- 导出 JSON 运行记录或 CSV 文献清单。
- 删除单条记录。
- 清空全部历史。

历史正文不默认渲染，避免与“直接用外部应用查看和编辑”的产品决策冲突。

### 7.3 设置

设置包含：

- DeepSeek API Key、连接状态和清除操作。
- My NCBI API Key、连接状态和清除操作。
- DeepSeek 模型选择，默认 Flash，可切换 Pro。
- 默认最大抓取量，默认 50。
- 本地存储用量。
- 清除历史和清除全部本地数据。

## 8. 本地数据模型

至少包含以下逻辑实体：

- AppSettings：密钥、默认模型、默认最大抓取量、设置版本。
- ReviewRun：任务 ID、输入主题、确认后的检索式、设置快照、状态、阶段、统计、时间戳和错误摘要。
- Article：内部来源 ID、PMID、标准化元数据、摘要和原始顺序。
- ScreeningDecision：任务 ID、文章 ID、相关性评分、纳入决定、原因和筛选提示词版本。
- GenerationArtifact：大纲、最终 Markdown、引用映射、参考文献和提示词版本。
- Checkpoint：阶段名称、完成状态、可恢复数据和更新时间。

数据库升级必须使用版本化迁移。任务、文章和检查点写入应使用事务，避免刷新或崩溃后出现半完成记录。

## 9. 安全与隐私

- API Key 仅保存在当前 GitHub Pages 源对应的浏览器存储中。
- 因用户选择持久保存，应用必须明确提示：同一设备的浏览器用户、恶意扩展或该网页未来被注入的脚本可能读取密钥。
- 密钥不得写入 URL、DOM 文本、控制台日志、错误遥测、导出文件或 Service Worker Cache。
- 项目不接入第三方分析、错误追踪或广告脚本。
- 提供一键清除密钥和一键清除全部本地数据。
- 使用严格 Content Security Policy，限制脚本和网络目标到应用自身、NCBI 和 DeepSeek 所需域名。
- 公开仓库不得包含任何真实密钥、token、Webhook ID、飞书配置或 n8n 凭据导出。

现有 n8n JSON 已包含明文凭据。发布前必须轮换其中暴露的 NCBI API Key 和飞书验证/加密凭据，即使新 PWA 不再使用飞书。

## 10. 任务状态与错误处理

任务状态至少包括：草稿、等待确认、抓取中、筛选中、生成大纲、生成正文、校验引用、生成 Word、已完成、已取消和失败。

- 网络中断：保存当前检查点，恢复网络后允许继续。
- NCBI `429` 或 `5xx`：遵守请求速率并使用带抖动的有限指数退避。
- DeepSeek `429` 或 `5xx`：有限重试；失败后保留上一个完整阶段。
- 无效密钥：停止任务并跳转到相应设置项，不反复重试。
- XML 部分损坏：记录受影响文章，继续处理其他有效文章；若整体响应不可解析则停止该阶段。
- 无有效摘要或无相关文献：停止后续生成，给出可操作的检索式调整建议。
- DeepSeek 返回格式无效：先尝试结构修复，再有限重试；不得静默接受缺失 ID 的筛选结果。
- 引用校验失败：不生成 Word，允许从正文生成或引用修复阶段重试。
- 存储空间不足：在写入前检查估算用量，提示用户删除历史或减少抓取量。

## 11. 离线行为

Service Worker 缓存应用外壳、图标和必要静态资源。离线时：

- 可以打开应用。
- 可以查看历史列表和任务统计。
- 可以从已保存的最终内容重新生成 Word、JSON 和 CSV。
- 不能测试密钥、查询 PubMed、执行筛选或生成综述。
- 所有依赖网络的操作应禁用并显示清晰的离线状态。

## 12. 测试策略

### 12.1 单元测试

- PubMed XML 的单摘要、多段摘要、缺失作者、团体作者和不完整日期解析。
- 无摘要文章过滤。
- 相关性结果的 ID 完整性、去重、稳定排序和排除逻辑。
- 上下文预算在已知与未知模型下的保守选择。
- 引用扫描、无效引用检测、首次出现顺序重排和参考文献裁剪。
- DOCX 结构、标题层级、正文引用和参考文献内容。
- 文件名清理和 CSV/JSON 导出不含密钥。

### 12.2 集成测试

- 使用模拟 NCBI 与 DeepSeek 响应覆盖完整状态机。
- 验证刷新、取消、断网和 API 重试后的检查点恢复。
- 验证原三组提示词的快照仅发生允许的变量占位符替换。
- 验证 Service Worker 不缓存 API 响应。
- 验证 IndexedDB 迁移和清除数据操作。

### 12.3 端到端测试

- 桌面和手机视口完成设置、检索式确认、生成、自动下载和历史再次下载。
- PWA 安装条件和 GitHub Pages 子路径部署。
- 离线启动、历史访问和离线重新导出。
- 无效密钥、限流、无摘要、无相关文献和引用修复失败路径。

CI 仅使用模拟 API。真实密钥测试只能由开发者在本机手动执行，密钥不得进入测试快照、录像或日志。

## 13. 验收标准

1. 构建产物可直接部署到 GitHub Pages，不需要任何后端服务。
2. 新设备首次使用可填写并验证用户自己的 DeepSeek 和 My NCBI API Key。
3. 用户可输入自然语言主题，编辑并确认 AI 生成的 PubMed 检索式。
4. 用户可将最大抓取量设置为 10–300，默认值为 50。
5. 应用能过滤无摘要和低相关文献，并按上下文预算动态确定入选集。
6. 原检索式、大纲和正文提示词内容得到保留，只有变量绑定方式发生迁移。
7. 最终自动下载的 DOCX 只包含中文综述正文及其真实映射的参考文献。
8. 无效引用编号不会进入导出的 DOCX。
9. 历史、摘要、中间结果和密钥只存于用户浏览器，不发送到自建服务或飞书。
10. 离线时可打开应用、查看历史并重新导出已完成的 Word。
11. 手机和桌面端均可完成核心流程，文本和控件不重叠。
12. 公开仓库和构建产物中不存在真实 API Key、飞书凭据或完整 n8n 凭据导出。
