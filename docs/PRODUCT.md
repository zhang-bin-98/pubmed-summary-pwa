# PubMed 综述 PWA 产品文档

## 1. 产品定位

PubMed 综述 PWA 是一个面向个人医学研究者的浏览器端工具。用户输入研究主题并使用自己的 AI 服务，应用会完成 PubMed 检索式生成、摘要获取、相关性筛选、中文综述写作、引用整理和 Word 导出。

产品强调三点：

- 纯前端：部署在 GitHub Pages，不依赖项目自建后端。
- 本地优先：设置、运行历史和生成结果保存在当前浏览器。
- 过程可追溯：写作证据来自 PubMed 元数据与摘要，并保留筛选结果和阶段检查点。

在线版本与基础使用方法见仓库根目录的 [README](../README.md)。

## 2. 目标用户与使用前提

主要用户是需要快速整理 PubMed 文献并形成中文综述初稿的医学研究者、临床科研人员和研究生。

用户需要：

- 自行提供一个可从浏览器访问的 OpenAI-compatible AI 服务及 API Key；
- 能够判断检索式是否符合研究问题；
- 对 AI 生成的医学内容和引用进行人工复核；
- 仅在可信设备和可信浏览器环境中使用自己的凭据。

本产品不是免凭据的公共生成服务，也不面向临床决策自动化或多人协作。

## 3. 核心使用流程

### 3.1 首次设置

1. 填写 Chat Completions Base URL 和 AI API Key。
2. 从自动拉取的模型列表中选择模型；如果服务不支持模型列表接口，可以手动填写模型 ID。
3. 填写模型上下文长度和默认抓取量。
4. 可选填写 My NCBI API Key；留空时使用匿名访问。
5. 分别测试 AI、NCBI 连接，或明确跳过对应测试后保存。

AI API Key 为必填项。NCBI API Key 为可选项，但无论是否填写，NCBI 连接都必须测试成功或由用户明确跳过，才能进入工作台。

### 3.2 一键生成

1. 输入研究主题，选择 AI 模型和最大抓取量。
2. 选择“一键生成”并开始任务。
3. 应用生成 PubMed 检索式并查询预计命中数。
4. 应用自动获取摘要、筛选相关文献、选择上下文、生成大纲和正文、校验引用。
5. 完成后自动下载 DOCX，并将运行记录保存在本地历史中。

### 3.3 确认检索式

“确认检索式”模式与一键模式使用相同的后续工作流，但会在正式抓取前展示 AI 生成的检索式和预计命中数。用户可以编辑检索式，再开始生成。

### 3.4 历史与恢复

历史页支持：

- 查看任务状态、更新时间、抓取量和正文实际引用量；
- 继续失败或取消的任务，复用已保存的阶段和筛选批次；
- 对已完成任务再次导出 DOCX；
- 导出 JSON 运行记录或 CSV 文献清单；
- 删除单条记录或清除全部历史，同时保留设置与 API Key。

## 4. 产品能力

### 4.1 PubMed 检索与解析

- 根据自然语言主题生成 PubMed 检索式。
- 在确认模式中允许用户修改检索式。
- 使用 NCBI ESearch 获取命中数和历史集合，使用 EFetch 分页获取 PubMed XML。
- 解析文章标题、摘要、作者、期刊、日期、卷期、页码和机构等字段。
- 单次任务的最大抓取量为 10–300 篇，默认 300 篇。
- 无摘要文献不会进入相关性筛选和写作上下文。

### 4.2 相关性筛选与上下文选择

- 基于研究主题、标题和摘要，为每篇文献生成 0–3 分、是否纳入及简短理由。
- 每个筛选批次最多 20 篇，并受估算输入长度约束。
- 多个筛选批次并行执行，完成后按 PubMed 原始顺序稳定合并。
- 每个完成批次立即保存筛选结果和检查点，任务恢复时只重跑未完成批次。
- 相关文献按相关性分数和原始顺序选择，受用户填写的模型上下文长度约束；不截断单篇摘要，也不设置固定入选篇数。

### 4.3 综述生成与引用处理

- 使用版本化的检索、大纲、写作和相关性筛选提示词。
- 当前所选模型用于检索式生成、相关性筛选、大纲和正文写作。
- 输出中文 Markdown 综述，再转换为 DOCX。
- 引用校验会检查编号是否对应证据文献，按正文首次出现顺序重新编号，并移除正文未引用的参考文献。
- 首次引用校验失败时会重新生成一次正文；第二次仍失败则停止导出，避免输出已知引用结构无效的文档。

引用校验只能验证编号和参考文献结构，不能自动证明某篇文献充分支持某项医学主张。

### 4.4 导出与本地记录

- DOCX：标题、分级正文和正文实际引用的参考文献。
- JSON：运行、文献、筛选决定和最终生成产物。
- CSV：PMID、标题、期刊、发表日期、是否纳入、分数和筛选理由。
- 网页不提供正文预览或富文本编辑；结果以下载文档和本地历史为主。
- 导出内容不包含 API Key。

### 4.5 PWA 与离线能力

应用可安装为 PWA。Service Worker 只预缓存应用静态资源，不对 NCBI 或 AI API 设置运行时缓存。

离线时可以打开已缓存的应用；在已保存的 AI Key 与连接决定仍满足入口门槛时，还可以查看本地历史并重新导出已有结果。离线状态不能发起新的 PubMed 检索、AI 筛选或综述生成。

## 5. 配置契约

| 配置 | 要求 | 当前行为 |
| --- | --- | --- |
| Chat Completions Base URL | 必填 | 默认 `https://api.deepseek.com`；必须是 HTTPS；应用在其后请求 `/models` 和 `/chat/completions` |
| AI API Key | 必填 | 通过 `Authorization: Bearer ...` 直接发送给用户配置的 AI 服务 |
| AI 模型 ID | 必填 | 填写 Base URL 与 Key 后自动尝试拉取；失败时可手动填写，默认 `deepseek-v4-flash` |
| 上下文长度 | 必填 | 默认 1,000,000，最低 16,000；用于选择可放入提示词的完整文献 |
| My NCBI API Key | 可选 | 空值或纯空白表示匿名访问，请求中不包含 `api_key` |
| 默认抓取量 | 必填 | 10–300，默认 300 |
| AI / NCBI 连接决定 | 必须完成 | 每项都需测试成功或明确跳过；跳过不代表连接已经验证 |

自定义 AI 服务需要支持：

- 浏览器跨域访问（CORS）；
- Bearer API Key；
- OpenAI-compatible `POST /chat/completions`；
- 推荐支持 `GET /models`，不支持时用户仍可手动填写模型 ID。

无 NCBI Key 时，页面内所有 `NcbiClient` 实例共享匿名请求调度器，出站尝试至少间隔 350 ms，以符合 NCBI 每个 IP 每秒最多 3 次请求的匿名配额。调度器不能协调其他标签页或同一公网 IP 下的其他客户端，遇到限流仍会使用有限重试作为兜底。具体政策以 [NCBI E-utilities 使用说明](https://www.ncbi.nlm.nih.gov/books/NBK25497/?report=printable) 为准。

## 6. 数据与隐私

### 6.1 保存在当前浏览器的数据

以下数据保存在当前站点来源的 IndexedDB 中：

- AI 和 NCBI 配置及 API Key；
- 任务主题、检索式、运行状态和统计信息；
- PubMed 元数据与摘要；
- 筛选决定、阶段检查点和生成产物。

项目没有自建后端、云数据库、账户系统、遥测或广告。清除浏览器站点数据会同时清除这些本地记录。

### 6.2 发送到外部服务的数据

- NCBI：检索式和请求参数；若已配置 NCBI API Key，它会随每个 NCBI POST 表单体发送。
- AI 服务：研究主题、提示词、PubMed 元数据与摘要、大纲和生成上下文，以及 AI API Key。

API Key 不写入 URL、运行导出文件或 Service Worker Cache。由于数据和凭据位于浏览器中，共用设备、浏览器扩展或被注入的同源脚本仍可能读取它们。

## 7. 产品边界

当前明确不提供：

- 注册登录、云同步、跨设备同步和多人协作；
- 服务端密钥代理、后台任务队列或隐藏代理；
- 付费全文抓取或绕过出版商权限；
- 浏览器内的综述预览和富文本编辑器；
- 自动发送到飞书或其他第三方内容平台；
- 离线检索、筛选和生成；
- 可配置的筛选并发策略；
- 对医学结论真实性、完整性或临床适用性的保证。

生成结果仅适合作为研究辅助材料和综述初稿，不构成医疗建议。用户应核对原始论文、引用关系和医学结论后再使用。

## 8. 产品级质量标准

- 静态构建可直接部署到 GitHub Pages，无需自建后端。
- 一键生成和确认检索式两种模式均能完成端到端流程。
- 无摘要和低相关文章在写作前被排除，上下文选择不截断单篇摘要。
- 已知无效的引用编号不能进入 DOCX。
- DOCX 仅包含生成正文及正文实际引用的参考文献。
- DOCX、JSON 和 CSV 导出均不包含 API Key。
- 中断后保留完整阶段和已完成筛选批次，可继续运行。
- 已保存设置仍满足入口门槛时，离线状态下可查看历史并重新导出，但不能启动网络任务。
- Service Worker 不缓存第三方 API 请求或响应。
- 仓库、构建物和测试数据不包含真实凭据。
